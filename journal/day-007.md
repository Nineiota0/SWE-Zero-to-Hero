### Mistakes / Bugs

Mistake 1) Accidentally mutating the original object

When writing updateInventory(), I initially used:

quantity: product.quantity += change

I learned that += modifies the original product.quantity, while product.quantity + change only calculates a new value without changing the original.

Mistake 2) Not correctly updating the final quantity

I initially wrote an if/else statement that didn't properly assign the calculated quantity to a variable. I also created a new object but wasn't using the result of my conditional logic.

I learned that I needed to calculate the proposed quantity, determine the final quantity, and then use that value when creating the new object.

Mistake 3) Forgetting to return the new object

In my first attempt at updateInventory(), I created newProduct but forgot to return it. I learned that creating a variable inside a function doesn't automatically return it.

Mistake 4) Passing an array instead of individual arguments

While testing sumAll(), I learned that sumAll(values) passes the entire array as one argument, while sumAll(...values) spreads its elements into separate arguments.

### What I learned

I learned how destructuring makes it easier to extract values from objects and arrays without repeatedly accessing their properties or indices. I also learned how spread syntax can create new arrays and objects, combine existing data, and update properties without modifying the original.

One of the most important things I learned was the difference between mutation and immutable updates. I now understand that using += on an object's property changes the original object, while using spread with a calculated value creates a new object.

I also learned that spread creates a shallow copy, meaning nested objects can still share references.

Lastly, I learned about Math.max() and how it can replace an if/else statement when I need to prevent a number from falling below a minimum value.
